Public projections convert them to 0.001-world-unit numbers. Geometry converts starting coordinates/destinations to this exact integer space. For each segment/hostile circle solve `A t² + B t + C = 0`; BigInt evaluates the discriminant, segment intersection, initial distance and equal-root comparisons. Comparison of radicals uses exact squared integer predicates, so simultaneous first contacts are retained without a floating epsilon. The stored mathematical contact point/parameter uses the pinned JavaScript Number square-root evaluation for audit/display; neither determines the authoritative stop or contact ordering.

For integer displacement `(dx,dy)` in milliworld units, `g=gcd(abs(dx),abs(dy))`. Every representable point exactly on the segment is `from+k*(dx/g,dy/g)`, integer `k` in `[0,g]`. Binary search exact polynomial predicates for the largest k **strictly before the first root**. Verify the resulting point is strictly farther than 20000 milliworld units from every hostile center. This is the closest representable on-path pre-contact point, including coprime diagonals; it does not round axes independently. Lattice spacing along some diagonals exceeds 0.001 world units: 0.001 is coordinate precision, not a promised along-path step size or added collision radius. If no later representable point is valid, k=0 leaves the formation at its valid starting position. Initial hostile distance <=20 is the explicit exception: form the encounter and block both without teleporting either, even if coincident.
