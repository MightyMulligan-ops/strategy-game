# Sovereign hosted pipeline repair — 2026-11-16

## False-success validator repair (current candidate)

The earlier sections below are historical. [Run 43888968238](https://github.com/MightyMulligan-ops/strategy-game/actions/runs/43888968238) exposed a separate **confirmed false-success defect**, not successful independent validation: Corepack failed with `EAI_AGAIN registry.npmjs.org` inside the network-disabled container, yet the validate job and publisher succeeded. The owner authorized this focused subscription-Codex repair, normal CI and its disposable PostgreSQL service, but no paid session/dispatch, queue, deployment or existing database access.

### Confirmed causes and trust gaps

1. The image prepared Corepack as root in its default home/cache. Runtime execution switched to a non-root UID and `HOME=/tmp`; that cache was unavailable under the new home, so Corepack tried to download pnpm after networking was disabled. A successful image build had not proved the actual runtime could execute pnpm offline. See [Corepack's cache configuration](https://github.com/nodejs/corepack#environment-variables).
2. Bash `-e` does not exit for a failed nonfinal command in an AND-list. The `pnpm build && ...` chain stopped, but subsequent Git commands succeeded and became the shell's final exit status. A tree comparison says nothing about whether checks ran. This is the documented [Bash errexit exception](https://www.gnu.org/software/bash/manual/html_node/The-Set-Builtin.html).
3. The publisher accepted `RECONSTRUCTED_NO_EXECUTION` as its only receipt. It had no independently checked evidence of build/typecheck/test/lint execution. That receipt proves patch reconstruction only.
4. The old sandbox checked its own mutable Git metadata; the outside check examined the separate original checkout. Neither was an independent host check of the tested workspace's bytes. This was a confirmed trust gap, not evidence that a worker exploited it.

### Corrected execution and publication guarantees

- `scripts/sovereign-validation.Dockerfile` installs exactly pnpm 12.18.0 with lifecycle scripts disabled under `/opt/sovereign`, verifies its version, and checks Git/Python availability. The absolute pnpm entry point and PATH no longer depend on a HOME-scoped Corepack cache. Runtime preflight checks the exact version under the actual non-root UID, read-only root filesystem, `HOME=/tmp` and disabled network before running application code.
- Clean replay still precedes dependency installation. Locked dependencies and `prepare:checks` (including Prisma engine/client preparation) run only on unchanged trusted source, before applying the generated patch. No OpenAI key or GitHub write permission is present in validation.
- The trusted host invokes build, typecheck, test and lint **separately**, each in a fresh restricted Docker container. Missing pnpm, nonzero status, spawn error, signal, timeout, interrupted checks or tree drift throw before later checks or receipt creation. There is no shell AND-list or fallback Git command whose success can mask a check failure. Container output is captured, never interpreted as Actions commands or receipt evidence.
- Each command has a five-minute hard-kill deadline. Failure triggers bounded removal of only its randomly named validation container, preserving the original error if cleanup fails. Node's synchronous child-process timeout otherwise defaults to SIGTERM and can keep waiting when the child handles that signal; see the [Node child-process documentation](https://nodejs.org/api/child_process.html#child_processspawnsynccommand-args-options). Production diagnostics expose fixed stage/status/signal/process codes only. CI smoke failures additionally emit a bounded, redacted, JSON-quoted output tail marked as untrusted diagnostic data.
- Source/dependencies are copied to a separate workspace; Git metadata, prior diagnostics and environment files are excluded. No receipt directory, `GITHUB_OUTPUT`, Docker socket, credential or host Git directory is mounted. Existing network/capability/user/resource restrictions remain. Fresh containers also prevent a background process from surviving a check and racing host verification.
- Initial copies exclude host-generated Python bytecode directories, and containers set `PYTHONDONTWRITEBYTECODE=1`. CI #204 identified a pre-existing test-generated `scripts/__pycache__/*.pyc` file at the initial tree check. This does not relax later tree verification: newly created non-ignored files still fail, including files under a bytecode directory.
- [CI #207](https://github.com/MightyMulligan-ops/strategy-game/actions/runs/43909572495) exposed pnpm attempting dependency tarball downloads after the workspace was copied under a different absolute path/home. Its five-minute timeout failed closed, without a receipt. pnpm 12 defaults [`verifyDepsBeforeRun`](https://pnpm.io/settings/build#verifydepsbeforerun) to `install`; relocated workspace/store metadata can trigger an implicit reinstall. Containers explicitly set `PNPM_CONFIG_VERIFY_DEPS_BEFORE_RUN=false`, including nested pnpm invocations. This only disables implicit dependency installation in the sandbox: the preceding trusted frozen install, pinned lockfile/package manager, full checks and exact-tree checks remain required. No dependency store, network access or credential is added to the sandbox.
- Before checks and after each successful check, the host reads expected objects from trusted Git and hashes the actual tracked file bytes/modes in the tested workspace. Missing/changed files, symlinked tracked paths and unexpected non-ignored files fail. Worker Git config/index/hooks cannot substitute a fake tree. Ignored build outputs/dependencies are not claimed to be part of the validated Git tree.
- Only complete success writes `validation-receipt.json`: schema/policy, repository, run/attempt, source/tree identity, exact image ID, pnpm version, disabled network, all four ordered successful command records and SHA-256 bindings for scope, manifest, patch, summary and replay receipt. The host rechecks bundle bytes before writing. An old replay receipt alone is rejected.
- The receipt's digest is transferred separately through the trusted validate-step/job output to `needs.validate.outputs.validation_sha256`. It is **not** supplied by an artifact file or worker output. The publisher requires a successful validate job and nonempty digest, then verifies the raw receipt digest, complete checks, context and every artifact binding before any GitHub request. Missing/incomplete/failed/skipped/edited/stale receipts or changed artifacts fail closed. The publisher still independently reconstructs the exact tree in a detached trusted index and creates only a draft PR.

Node's `24-bookworm` base tag remains mutable: pnpm/version and lockfile are pinned, and the exact built image ID is recorded, but bit-for-bit reproducible images/build output are not claimed. No historical false-green receipt is upgraded or replayed as valid evidence.

The overnight queue remains unimplemented/disabled, the hosted pilot stays manual, and no internal spending cutoff, paid retry, automatic merge or deployment is added.

## Confirmed defects repaired

1. **Lost diagnostics:** top-level catches discarded errors and transports discarded HTTP metadata. Versioned JSON now records stage, safe local code, HTTP status, request/client-request IDs, known session/turn IDs and allowlisted provider codes. Error messages, stacks, response bodies, raw headers, issue text, model output and credentials are excluded. Unknown codes become fixed generic labels. Primary and cleanup failures remain separate records.
2. **Lost recovery evidence:** live journal state existed only in memory and success-only artifact upload skipped failures. Journal transitions also write runner-local metadata; an existing journal blocks another create in that directory. A separate `always()` artifact retains only sanitized diagnostics/journal. This is not cross-run durable storage: a forcibly terminated runner can still prevent upload. Request IDs are logged before/after requests to support reconciliation without replaying an ambiguous create.
3. **Unsupported stream assumptions:** parsing required illustrative `sess_`/`turn_` prefixes, although the public schemas define opaque strings. Bounded path-safe IDs now work throughout. The 32 KiB event ceiling was incompatible with observed tool-result sizes. SSE buffering also rejected a coalesced chunk before splitting valid events. Limits now apply to individual/unfinished records, retaining a bounded total stream.
4. **Certain downstream validation failure:** dependencies were installed before replay, but replay deliberately rejects all dirty/ignored checkout files. Installed `node_modules` would cause `dirty-source` even for a valid patch. Replay now runs first on a clean checkout, then trusted locked dependencies are installed, then the reconstructed patch is applied. The cleanliness/scope guards remain intact. A real temporary-Git Python regression reproduces this ordering requirement.
5. **Cleanup hid the cause and could not handle active work:** a DELETE conflict previously failed immediately and could replace the primary error. Cleanup now sends the documented cancel event on the first 409 and attempts at most three deletions, requiring matching deletion confirmation. These are cleanup-only retries, never repeated session creation or task input. A 13-minute stream deadline leaves time inside the 15-minute job for cleanup. Unconfirmed cleanup blocks proposal delivery.

## Current official API contract

Reviewed 2026-11-16; these checks do not establish that the real project/key has access:

- [Quickstart](https://developers.openai.com/api/docs/guides/agents-api/quickstart): application-key scopes `api.agents.read`, `api.agents.write`, `api.responses.write`; raw HTTP requires `OpenAI-Beta: agents=v1`. The key stays outside generated code. Model access and the key's actual assignments require separate verification.
- [RBAC](https://developers.openai.com/api/docs/guides/rbac): Files API permissions also matter for `/v1/files`; both the key and underlying project role must grant the required access. An executor-only credential is not an application credential.
- [File upload](https://developers.openai.com/api/reference/resources/files/methods/create): multipart `purpose=user_data`, archive content and the existing one-hour expiry are supported. Completed upload `bytes` can be null. No speculative upload-purpose/expiry change was made.
- [Create session](https://developers.openai.com/api/reference/resources/beta/subresources/agents/subresources/sessions/methods/create) and [hosted setup](https://developers.openai.com/api/docs/guides/agents-api/environments/openai-hosted): inline agent/model/instructions, `stream:true`, medium hosted environment, disabled network, absolute `/workspace` Files attachment and ordered setup commands match the documented request. No secret is included in environment/input.
- [Events](https://developers.openai.com/api/docs/guides/agents-api/sessions/events): consume session/turn/environment payloads by type; root completion requires null `subagent_id`. Idle, subagent completion and observer disconnection are not success. Raw streamed output is never logged.
- [Artifacts](https://developers.openai.com/api/reference/resources/beta/subresources/agents/subresources/sessions/subresources/artifacts/methods/list): retain cursor pagination, session/turn/path binding, exact three-file inventory and streaming byte bounds. Download before deleting the session.
- [Cancellation](https://developers.openai.com/api/docs/guides/agents-api/sessions#cancel-an-active-turn) and [deletion](https://developers.openai.com/api/reference/resources/beta/subresources/agents/subresources/sessions/methods/delete): cancel with `POST /agents/sessions/{id}/events` and `agent.session.input.cancel`; confirm deletion separately. Closing SSE alone does not stop work.

The native HTTP adapter has no SDK automatic retries. Source upload and paid session creation each occur once. Uploaded source retains its existing one-hour expiry.
